Requerimientos DevOps
Feature: Objetivo global de CI/CD para el Sistema de Insignias

  Scenario: Validar cambios en ambiente efímero antes de deploy
    Given existe un cambio en el repositorio y se requiere validar el Sistema de Insignias
    When el pipeline crea un ambiente efímero, ejecuta las pruebas y registra resultados
    Then si todas las pruebas pasan, se despliega automáticamente al ambiente destino

Feature: Disparador del pipeline

  Scenario: Ejecutar CI en cambios relevantes
    Given se hace push o PR a ramas "dev" o "main"
    When GitHub Actions inicia el workflow de CI
    Then el pipeline continúa con build y validaciones

Feature: Ambiente efímero

  Scenario: Provisión mínima para validar sin afectar producción
    Given se requiere un entorno aislado para validar cambios
    When el pipeline levanta un ambiente efímero con backend, frontend y base de datos
    Then el ambiente queda listo para pruebas y será eliminado al finalizar

Feature: Pruebas automáticas

  Scenario: Ejecutar pruebas y fallar rápido si hay errores
    Given el ambiente efímero está listo
    When se ejecutan pruebas (unitarias/integración) y linters
    Then el pipeline marca fallo si alguna prueba falla

Feature: Reglas de despliegue

  Scenario: Desplegar solo si las pruebas pasan
    Given el reporte de pruebas del ambiente efímero es exitoso
    When el pipeline llega a la fase de despliegue
    Then se promueven artefactos y se despliega al ambiente correspondiente

Feature: Backend en PythonAnywhere

  Scenario: Actualización controlada del backend
    Given el backend pasó pruebas en el ambiente efímero
    When se ejecuta el job de deploy con credenciales seguras
    Then la app Flask se actualiza y responde OK en el healthcheck "/health"

Feature: Frontend en Netlify

  Scenario: Publicación del frontend
    Given el build del frontend fue exitoso en el ambiente efímero
    When se ejecuta el job de deploy a Netlify con token seguro
    Then el sitio queda publicado y su URL se registra en la salida del job

Feature: Configuración y secretos

  Scenario: Manejo seguro de variables
    Given se requieren credenciales y configuración por entorno
    When el pipeline accede a variables y secretos desde el almacén de GitHub
    Then las credenciales no se imprimen en logs ni se versionan en el repo

Feature: Base de datos y migraciones

  Scenario: Aplicar migraciones de forma idempotente
    Given hay cambios en el esquema del sistema de insignias
    When se aplican migraciones antes de iniciar la app en despliegue
    Then la operación es idempotente y no genera duplicados ni errores

Feature: Observabilidad mínima

  Scenario: Verificación post-deploy
    Given el despliegue fue realizado
    When se corre un healthcheck y una prueba de humo
    Then se registra el resultado y se notifica al equipo si hay fallos

Feature: Limpieza del ambiente efímero

  Scenario: Teardown al finalizar
    Given terminaron las pruebas y/o el despliegue
    When el pipeline ejecuta la fase de cleanup
    Then el ambiente efímero se elimina y se liberan recursos
